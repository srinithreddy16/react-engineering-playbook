What is Virtual DOM?
====================
-The Virtual DOM is a lightweight JavaScript representation of the real DOM.
-It is a tree of JavaScript objects representing UI elements, their attributes, and content.
-Whenever state or props change, React creates a new Virtual DOM tree.
-React compares the new Virtual DOM with the previous Virtual DOM using a process called Diffing.
-After identifying the changes, React updates only the required parts of the real DOM.
-This process is called Reconciliation.
-React never reads from real DOM, only writes to it.
-The Virtual DOM helps React optimize rendering performance.

 
How Does React Work? (Virtual DOM)
==================================
1. Initial Render : When the application loads, React creates a Virtual DOM tree based on the Real DOM.

2. State or Props Change : Whenever state or props change (such as user input or API response), React creates a new Virtual DOM tree with the updated data.

3. Diffing : React compares the new Virtual DOM with the previous Virtual DOM tree to identify what has changed.

4. Reconciliation : Based on the diffing result, React determines the minimum changes required in the real DOM.

5. Real DOM Update : React updates only the changed parts of the real DOM instead of re-rendering the entire page, resulting in faster UI updates.

React Reconciliation 
====================
-Reconciliation is the process through which React updates the DOM.
 (syncing the Virtual DOM to the actual DOM)
-Reconciliation is the mechanism that tracks changes in a component state and renders the updated state to the screen.
-It's a step that happens between the render() function being called and the displaying of elements on the screen. This entire process is called reconciliation.

When to use a Class Component over a Function Component?
========================================================
-If the component needs state or lifecycle methods then use class component otherwise use function component. 
-However, from React 16.8 with the addition of Hooks, we can use state , lifecycle methods and other features that were only available in class component in function component also. 
-So, it is always recommended to use Function components, unless you need a React functionality whose Function component equivalent is not present yet, like Error Boundaries.

Limitations of Local Variables
==============================
No re-rendering : Changing a Local variable doesn't re-render, the component won't update to reflect the new value.
No Persistence : Local variable are re-created on each render, any changes made to them are lost after re-render


STATE VARIABLE:
A state variable is a piece of data that a component "remembers" between renders — and when it changes, React automatically re-renders the component to reflect that change on screen.
Short definition
A state variable holds data that can change over time (like user input, a counter, or a toggle), and updating it causes the UI to automatically update to match.
Why not just use a normal variable?
tsx
function Counter() {
  let count = 0;

  const increment = () => {
    count = count + 1;
    console.log(count); // this DOES increase
  };

  return (
    <div>
      <p>{count}</p>
      <button onClick={increment}>+1</button>
    </div>
  );
}

This looks like it should work — but it won't update the screen. The value of count does change internally, but React has no idea it needs to re-render. A normal variable is just memory that gets wiped and reset every time the component re-renders anyway.



Why State variables

Re-rendering : when state variable changes, React re-renders the component with new value
Persistence : states are persisted accross re-renders

React.memo()
============
-Introduced in React v16.6.
-React.memo() is a Higher-Order Component (HOC).
-It is used to improve performance by preventing unnecessary re-renders.
-It is used with child components that receive props.
-When a component is wrapped with React.memo(), React re-renders it only when its props change.
-React.memo() performs a shallow comparison of props. If the props are unchanged, React reuses the previous rendered result.
-Avoids unnecessary re-rendering when parent components re-render.
  
React.memo — My Notes

What I observed:
When my parent component (Counter) changes any state (like count), all its child components re-render again and again — even if that changed data is not being sent to them as props.

Specific case:

count is not a prop for UserCard.
But when I do Increment / Decrement / Reset on count, UserCard still re-renders every single time.

The question I asked myself:

When count is not even a prop for UserCard, why should UserCard re-render just because count is changing in my parent?

Answer — this is default React behavior:
By default, whenever a parent re-renders, React re-renders all its children too — regardless of whether that specific child's props actually changed.

That's why we use memo:
React.memo wraps a component and tells React: "Only re-render me if my own props change. If my props are the same as last time, skip re-rendering me."

Result:
So now, if UserCard's props (name, age, address) stay the same, UserCard will not re-render — even if count keeps changing in the parent.

One-line takeaway:

memo = "don't re-render me just because my parent re-rendered — only re-render me if MY props actually change."

Refs (Template Reference Variable)
==================================
-Refs are mainly used when we need to work with the DOM directly instead of using React state.
-Refs provide a way to access DOM nodes or React elements.
-Managing focus, text selection , animations.
-ex: this.myRef1 = React.createRef();  (class component)
     const myRef1 = useRef();          (function component)
	 const myRef1 = useRef<HTMLInputElement>(null);
     

-React supports another way to set refs called “callback refs”, 
 which gives more fine-grain control over normal refs when refs are set and unset.
 ex: <input ref={x => inputRef1=x} />
     alert(inputRef1.value)
	 
-'Ref forwarding' is a feature that lets some components take a ref they receive,and pass/forward it further down to a child.

useRef gives you a direct handle to a real DOM element, like the input box on the page. You do not store the typed text in state. You read it only when you need it (when Add is clicked).

Why useRef here?
With useState, every keystroke would update state and re-render the component.

With useRef:

typing does not re-render
React is not tracking the input value
on click, you read the input’s current value from the DOM
So useRef is useful when you only need the value at one moment (the button click), not on every change.

Think of it as: “Give me a pointer to this input, so I can read .value later.”

The refs
const inputRef1 = useRef<HTMLInputElement>(null)
const inputRef2 = useRef<HTMLInputElement>(null)
Each ref is a box. After render, inputRef1.current is the first <input> DOM node.

null is the start value, because the input does not exist yet. After React draws the page, .current points to the input.

HTMLInputElement is only TypeScript: this ref is for an input.

Connecting ref to the input
<input ref={inputRef1} />
<input ref={inputRef2} />
ref={inputRef1} means: “this input is inputRef1.current.”

The Add function
const val1 = +(inputRef1.current?.value || 0);
const val2 = +(inputRef2.current?.value || 0);
Part	Meaning
inputRef1.current
the first input element
.value
the text inside it ("10" is a string)
?.
if .current is null, don’t crash
|| 0
if empty/null, use 0
+
convert string to number ("10" → 10)
Then:

console.log(`Addition of ${val1} and ${val2} is ${val1 + val2}`);
If you type 10 and 20 and click Add, the console shows:

Addition of 10 and 20 is 30
Flow
1. Page loads. Refs are created (current = null).
2. React renders the two inputs and attaches the refs.
3. You type 10 and 20. No re-render.
4. You click Add.
5. addition() reads both .value from the DOM.
6. Converts to numbers and logs the sum.

Forms
=====
-Forms are used to collect User Data.
-control the values of more than one input field by adding a name attribute to each element.
-get the field value by using the 'event.target.value', 
 get the field name by using 'event.target.name'
-control the submit action by adding an event handler with onSubmit attribute.
  <form onSubmit={this.submitHandler}> 
    <button>submit</button>
  </form>
-use event.preventDefault() to prevent the form from actually being submitted.(to avoid page refresh)

-A form can be validated on change or while submitting the form.
-The textarea element in React is slightly different from HTML Syntax.
-In HTML the value of a textarea was the text between the start tag <textarea> and the end tag </textarea>,
 in React the value of a textarea is placed in a value attribute:
   <textarea value={this.state.description} />   correct
   <textarea>{this.state.description}<textarea>  wrong
-A drop down list, or a select box, in React is also a bit different from HTML.
-in HTML, the selected value in the drop down list was defined with the selected attribute:
	 <select value={this.state.mycar}>
        <option value="Ford">Ford</option>
        <option value="Volvo">Volvo</option>
        <option value="Fiat">Fiat</option>
      </select>   //correct
	  
	<select>
	  <option value="Ford">Ford</option>
	  <option value="Volvo" selected>Volvo</option>
	  <option value="Fiat">Fiat</option>
	</select> //wrong
