What is Virtual DOM?
====================
-The Virtual DOM is a lightweight JavaScript representation of the real DOM.
-It is a tree of JavaScript objects representing UI elements, their attributes, and content.
-Whenever state or props change, React creates a new Virtual DOM tree.
-React compares the new Virtual DOM with the previous Virtual DOM using a process called Diffing.
-After identifying the changes, React updates only the required parts of the real DOM.
-This process is called Reconciliation.
-React never reads from real DOM, only writes to it.
-The Virtual DOM helps React optimize rendering performance.

 
How Does React Work? (Virtual DOM)
==================================
1. Initial Render : When the application loads, React creates a Virtual DOM tree based on the Real DOM.

2. State or Props Change : Whenever state or props change (such as user input or API response), React creates a new Virtual DOM tree with the updated data.

3. Diffing : React compares the new Virtual DOM with the previous Virtual DOM tree to identify what has changed.

4. Reconciliation : Based on the diffing result, React determines the minimum changes required in the real DOM.

5. Real DOM Update : React updates only the changed parts of the real DOM instead of re-rendering the entire page, resulting in faster UI updates.

React Reconciliation 
====================
-Reconciliation is the process through which React updates the DOM.
 (syncing the Virtual DOM to the actual DOM)
-Reconciliation is the mechanism that tracks changes in a component state and renders the updated state to the screen.
-It's a step that happens between the render() function being called and the displaying of elements on the screen. This entire process is called reconciliation.

React.StrictMode
================
-StrictMode is a React development tool used for identifying potential problems in an application.
-It enables additional checks and warnings for its descendant components.
-StrictMode checks run only in development mode and do not affect the production build.
-StrictMode helps with the following:
    • Identifying unsafe lifecycle methods
    • Warning about legacy string ref API usage
    • Warning about deprecated findDOMNode() usage
    • Detecting unexpected side effects
    • Detecting legacy context API usage
    • Detecting components with non-reusable state

When to use a Class Component over a Function Component?
========================================================
-If the component needs state or lifecycle methods then use class component otherwise use function component. 
-However, from React 16.8 with the addition of Hooks, we can use state , lifecycle methods and other features that were only available in class component in function component also. 
-So, it is always recommended to use Function components, unless you need a React functionality whose Function component equivalent is not present yet, like Error Boundaries.


Fragments
=========
-While returning elements in JSX, we can only return 1 element at a time.
 That element can have children but we have to ensure that we are only returning 1 element at a time, or else we will get a syntax error. (ex: a function can return 1 value)
-Fragments are way to render multiple elements without using a wrapper element.
-Fragment acts as a wrapper without adding unnecessary divs to the DOM. 
-We can use it directly from the React import, or deconstruct it.
	  import React from 'react';
	  <React.Fragment>
        <div>I am an element!</div>
        <button>I am another element</button>
      </React.Fragment>
-// Deconstructed
	import { Fragment } from 'react';
	<Fragment>
        <div>I am an element!</div>
        <button>I am another element</button>
     </Fragment>
-React version 16.2 simplified this process further, allowing for empty JSX tags to be interpreted as Fragments
   <>
		<div>I am an element!</div>
		<button>I am another element</button>
   </>

Data Binding
===============
-Binding/Displaying the variable value in UI is called data binding.
-React primarily uses one-way data binding.
-Two-way binding can be implemented manually using state, value, and onChange handlers.

Binding Type   | Description                     | React Example
---------------|---------------------------------|----------------
One-way Binding| State → UI                      | {value}
Two-way Binding| State ↔ UI using `onChange`     | {value + onChange}

ex:
function App() {
  const [name, setName] = useState("");
  return (
    <input value={name} onChange={(e) => setName(e.target.value)} />
  );
}

Limitations of Local Variables
==============================
No re-rendering : Changing a Local variable doesn't re-render, the component won't update to reflect the new value.
No Persistence : Local variable are re-created on each render, any changes made to them are lost after re-render


STATE VARIABLE:
A state variable is a piece of data that a component "remembers" between renders — and when it changes, React automatically re-renders the component to reflect that change on screen.
Short definition
A state variable holds data that can change over time (like user input, a counter, or a toggle), and updating it causes the UI to automatically update to match.
Why not just use a normal variable?
tsx
function Counter() {
  let count = 0;

  const increment = () => {
    count = count + 1;
    console.log(count); // this DOES increase
  };

  return (
    <div>
      <p>{count}</p>
      <button onClick={increment}>+1</button>
    </div>
  );
}

This looks like it should work — but it won't update the screen. The value of count does change internally, but React has no idea it needs to re-render. A normal variable is just memory that gets wiped and reset every time the component re-renders anyway.



Why State variables
===================
Re-rendering : when state variable changes, React re-renders the component with new value
Persistence : states are persisted accross re-renders

Props
=====
-Props stands for Properties. Props are inputs to components.
-Props are used to pass data and methods from a parent component to a child component.
-Attributes passed to components are received as an object called props.
-Props help make components reusable and dynamic.
-Data passed using props flows in one direction (Parent → Child). This is called unidirectional data flow.
-We can pass props to components similar to HTML attributes.

Example:
---------
<ChildComponent name="John" age={25} />
-Boolean props passed without a value are treated as true.
	<MyComponent showTitle={true} />
	<MyComponent showTitle />

-Props can be accessed as shown below:
	Class Component: this.props.propName
	Functional Component: props.propName


Important Points about props
=============================
1. Props are immutable.
   -Child components should not modify props received from parent components.
2. Props support unidirectional data flow.
   -Data flows only from Parent → Child.
3. Props help create reusable components.
4. When parent data changes, updated props are automatically passed to child components.

Component vs PureComponent
==========================
-PureComponent is exactly the same as Component except that it handles the 
 'shouldComponentUpdate' method for us. 
-When props or state changes, PureComponent will do a shallow comparison on both props and state.if there is a change in state/props, then only render() will be called. 
-A normal Component always calls render() when we update the state. even though there is no change in the last state data and current state data.
-Class components that extend the React.PureComponent class are treated as pure components.
	Ex: class myComp extends React.PureComponent {
		}
		
-Every Functional Component is a Pure-Component.
-PureComponent checks previous State and new State , if nothing changed , it skips re-rendering

   const updateName = () => {setName("pavan")};


React.memo()
============
-Introduced in React v16.6.
-React.memo() is a Higher-Order Component (HOC).
-It is used to improve performance by preventing unnecessary re-renders.
-It is used with child components that receive props.
-When a component is wrapped with React.memo(), React re-renders it only when its props change.
-React.memo() performs a shallow comparison of props. If the props are unchanged, React reuses the previous rendered result.
-Avoids unnecessary re-rendering when parent components re-render.
