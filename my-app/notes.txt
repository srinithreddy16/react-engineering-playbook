What is Virtual DOM?
====================
-The Virtual DOM is a lightweight JavaScript representation of the real DOM.
-It is a tree of JavaScript objects representing UI elements, their attributes, and content.
-Whenever state or props change, React creates a new Virtual DOM tree.
-React compares the new Virtual DOM with the previous Virtual DOM using a process called Diffing.
-After identifying the changes, React updates only the required parts of the real DOM.
-This process is called Reconciliation.
-React never reads from real DOM, only writes to it.
-The Virtual DOM helps React optimize rendering performance.

 
How Does React Work? (Virtual DOM)
==================================
1. Initial Render : When the application loads, React creates a Virtual DOM tree based on the Real DOM.

2. State or Props Change : Whenever state or props change (such as user input or API response), React creates a new Virtual DOM tree with the updated data.

3. Diffing : React compares the new Virtual DOM with the previous Virtual DOM tree to identify what has changed.

4. Reconciliation : Based on the diffing result, React determines the minimum changes required in the real DOM.

5. Real DOM Update : React updates only the changed parts of the real DOM instead of re-rendering the entire page, resulting in faster UI updates.

React Reconciliation 
====================
-Reconciliation is the process through which React updates the DOM.
 (syncing the Virtual DOM to the actual DOM)
-Reconciliation is the mechanism that tracks changes in a component state and renders the updated state to the screen.
-It's a step that happens between the render() function being called and the displaying of elements on the screen. This entire process is called reconciliation.

STATE VARIABLE:
A state variable is a piece of data that a component "remembers" between renders — and when it changes, React automatically re-renders the component to reflect that change on screen.
Short definition
A state variable holds data that can change over time (like user input, a counter, or a toggle), and updating it causes the UI to automatically update to match.
Why not just use a normal variable?
tsx

  let count = 0;

  const increment = () => {
    count = count + 1;
    console.log(count); // this DOES increase
  };

  return (
    <div>
      <p>{count}</p>
      <button onClick={increment}>+1</button>
    </div>
  );
}

This looks like it should work — but it won't update the screen. The value of count does change internally, but React has no idea it needs to re-render. A normal variable is just memory that gets wiped and reset every time the component re-renders anyway.

React.memo()
============
-Introduced in React v16.6.
-React.memo() is a Higher-Order Component (HOC).
-It is used to improve performance by preventing unnecessary re-renders.
-It is used with child components that receive props.
-When a component is wrapped with React.memo(), React re-renders it only when its props change.
-React.memo() performs a shallow comparison of props. If the props are unchanged, React reuses the previous rendered result.
-Avoids unnecessary re-rendering when parent components re-render.
  
React.memo — My Notes

What I observed:
When my parent component (Counter) changes any state (like count), all its child components re-render again and again — even if that changed data is not being sent to them as props.

Specific case:

count is not a prop for UserCard.
But when I do Increment / Decrement / Reset on count, UserCard still re-renders every single time.

The question I asked myself:

When count is not even a prop for UserCard, why should UserCard re-render just because count is changing in my parent?

Answer — this is default React behavior:
By default, whenever a parent re-renders, React re-renders all its children too — regardless of whether that specific child's props actually changed.

That's why we use memo:
React.memo wraps a component and tells React: "Only re-render me if my own props change. If my props are the same as last time, skip re-rendering me."

Result:
So now, if UserCard's props (name, age, address) stay the same, UserCard will not re-render — even if count keeps changing in the parent.

One-line takeaway:

memo = "don't re-render me just because my parent re-rendered — only re-render me if MY props actually change."

useMemo()
=========
-The functions called inside a component are re-invoked on every state change.
-If we want a function to run only on component load (or only when some values change), and not on every state change, use useMemo() for that calculation.
-useMemo() is used to cache (memoize) the result of an expensive calculation.
-It helps avoid unnecessary re-calculations during re-renders.
-useMemo() returns a memoized value.
-useMemo(() => {}, []) accepts a second parameter to declare dependencies.
-The function passed to useMemo() executes only when one of its dependencies changes.
-If the dependency array is empty ([]), the calculation runs only on the initial render.
-useMemo() should be used for expensive calculations such as filtering, sorting, or complex computations.
-The main difference between useMemo() and useCallback():
-useMemo() returns a memoized value, whereas useCallback() returns a memoized function.


useCallback()
=============
-useCallback() is a React Hook that returns a memoized version of a function.
-It helps prevent unnecessary re-creation of functions during component re-renders.
-It is used when passing functions as props to child components.
-It preserves the same function reference between parent renders unless its dependencies change.

-Without useCallback(), a new function object is created every time the parent component renders.
-When this function is passed as a prop to a child component, the child may re-render because the prop reference has changed
-This can cause child components to re-render unnecessarily(even if the child is using React.memo())

Example of useCallback() - consider components Counter.tsx(parent) and UserCard.tsx(child):
React.memo — Notes (Parent-Child Props Behavior)

Default behavior (without memo):
By default, whenever the parent (Counter.tsx) re-renders, the child (UserCard.tsx) also re-renders — even if the props passed to it (name, age, address) did not change.

Case 1: Parent passes only data 
Right now, Counter.tsx is passing only plain data (name, age, address) to UserCard.tsx, and UserCard is wrapped in React.memo(). Because of this, when I click Increment / Decrement / Reset in the parent, UserCard does not re-render unnecessarily — since those actions only change count, and count doesn't affect UserCard's props at all. This is exactly why we use React.memo() — to skip re-rendering the child when its own props haven't changed.

Case 2: Parent passes a function
If the parent later passes a function as a prop to UserCard (instead of just plain data), then Increment / Decrement / Reset will start re-rendering UserCard again — even with React.memo() applied. This happens because a new function is created every time the parent re-renders, and React.memo() sees that new function reference as a "changed prop" — so it re-renders the child anyway.

One-line takeaway:
React.memo() works fine when props are plain data. But if a prop is a function, a new function is created on every parent render — so React.memo() gets tricked into thinking props changed, and re-renders anyway.

Now our requirement is When a function is passed as a prop from parent to child, the child should not re-render for parent state changes if its other props stay the same. To achieve this, wrap that function in useCallback() in the parent. useCallback() keeps the same function reference across parent re-renders, so React.memo on the child can skip unnecessary re-renders.


SyntheticEvent
==============
-Instead of working directly with the browser's native event system(MouseEvent, KeyboardEvent, PointerEvent, etc.), 
 React provides its own event system called SyntheticEvent/SyntheticBaseEvent.
-A SyntheticEvent is a cross-browser wrapper around the browser's native event.
-It normalizes browser differences, ensuring that events behave consistently across different browsers(Chrome, Firefox, Safari)
-In React, event handler functions receive a SyntheticEvent object as an argument instead of the browser's native Event object.
-SyntheticEvent provides the same interface as native events, including properties and methods such as:
    * target
    * currentTarget
    * preventDefault()
    * stopPropagation()	
-If access to the underlying native browser event is required, it can be obtained using: event.nativeEvent

Example:
---------
function handleClick(event) {
    console.log(event);             // SyntheticEvent
    console.log(event.nativeEvent); // Native browser event
}
<button onClick={handleClick}>Click Me</button>

Advantages:
-----------
1. Cross-browser compatibility.
2. Consistent event behavior across all supported browsers.
3. Improved performance through React's event delegation mechanism.
4. Simplifies event handling for developers.

Routing
=======
-Single Page Applications (SPAs) load a single HTML page and dynamically update content without reloading the entire page.

-Routing enables navigation between different views or components within an SPA.
-When a user clicks a link or the URL changes, React Router renders the appropriate component without refreshing the page.
-Routing keeps the browser URL synchronized with the application's current view.
-Browser Back and Forward buttons work seamlessly, just like in traditional websites.
-It connects application navigation with browser navigation features such as the address bar, history stack, and navigation buttons.
-React Router allows us to display specific components based on the current URL (route) that matches the requested path.

-Below are the 3 components used the most while working with React Router are:
	1. BrowserRouter, usually aliased as Router (wraps all your Route components)
	2. Link		(used to generate links to your routes)
	3. Route    (showing or hiding the components they contain)



Steps for Routing
=================
1. Install  React Router DOM
   npm install react-router-dom   
2. Create Pages/Components
   create components like - (Home,About,Contact,Careers,NotFound)   
3. set up the application to work with React Router. (index.js / main.tsx)
   import { BrowserRouter } from 'react-router-dom';	
   <BrowserRouter>
        <App />
   </BrowserRouter>	
4. add the <Routes> element (ensures that only one component is rendered at a time)
   and add <Route> to create the link between components    (Body.js)
    <Routes>
        <Route exact path="/" element={<Home />} />
        <Route exact path="/home" element={<Home />} />
        <Route exact path="/aboutus" element={<AboutUs />} />
        <Route exact path="/products" element={<Products />} />
        <Route path="*" element={<NotFound />} /> (No Match Route)
    </Routes>	
5. Add a Link for each component and use to="URL" to link them.
		<ul className="navbar-nav me-auto mb-2 mb-lg-0">
            <li className="nav-item">
              <Link className="nav-link" to="/home">Home</Link>
            </li>
            <li className="nav-item">
              <Link className="nav-link" to="/aboutus">AboutUs</Link>
            </li>
            <li className="nav-item">
              <Link className="nav-link" to="/careers">Careers</Link>
            </li>
            <li className="nav-item">
              <Link className="nav-link" to="/contactus">Contact Us</Link>
            </li>
         </ul>

Link vs NavLink
===============
<Link> does not automatically apply any styling to the currently active route.
<NavLink> is similar to <Link>, but it automatically adds an 'active' class to the link that matches the current URL.
-This makes it easy to highlight the currently selected navigation item.
ex: <NavLink to='home' className='nav-link'>Home</NavLink>

-add below css: 
	nav .active{background-color: aquamarine;}
	


Navigate from one Route to another Route
=========================================
-Using <a> tag is not recommended because it refreshes the entire application.
	<a href="/home">Go To Home</a>

-Using <Link> is recommended because it navigates without reloading the page.
	<Link to="/home">Go To Home</Link>

Route Params
============
1. Path params    (userdetails/1)
2. Query Params   (search?name=sachin&age=25)


Path Params
-----------
1. configure the route
   <Route path="/userdetails/:id" element={<UserDetails />} />
   
2. create a link to that route (UserList - for Every User)
   <Link to={`/userdetails/${id}`}>Details</Link>
   
3. Read the Parameter data and display
   const { id } = useParams();
   <h1>This is the details of product - {id}</h1>


Query params
------------
1. configure the route
   <Route path="/productdetails" element={<ProductDetails />} />
   
2. create a link & navigation logic (ProductList page)
  const navigate = useNavigate();
  const navigateHandler = (title, price) => {
    navigate({
      pathname: "/productdetails",
      search: `?${createSearchParams({ title, price })}`,
    });
  };
   <button className="btn btn-secondary" onClick={() => {
              navigateHandler(title, price);
            }}>details</button>

3. collect params data and display
    const [searchParams] = useSearchParams();
    const id = searchParams.get("id");
    const title = searchParams.get("title");
    const price = searchParams.get("price");
    return <>
            <h2>Product Details</h2>
            <p>Id : {id}</p>
            <p>Title : {title}</p>
            <p>Price : {price}</p>
        </>
	
  
Note: To get all the query params as object, below code can be used
      productObj = Object.fromEntries([...searchParams]);

Index Route: We use index route When parent component loads along with parent component one of the child component by default should load
===========
-an index route is a special child route that renders by default when parent route loads/matches.
<Route path="/careers" element={<Careers />}>
    <Route index element={<PermanentJobs />} />

Protected Routes
================
-Protected Routes are routes that can only be accessed if a condition is met(usually, if user is properly authenticated). 
-It returns a Route that either renders a component or redirects a user to another route based on a set condition.

-create a component that accepts another component and other route details as props.
-check a condition to confirm if user is authenticated or not. 
-if the value is true, render the component, else, Redirect route to /signin page.


Replace
=======
-replaces the current location instead of pushing a new one onto the browser history stack.
-Without replace : Adds a new entry to the browser history (Back button will go back)
-With replace : Replaces current URL (Back button won’t return to the previous URL)
-HTML Code : <Navigate to="/home" replace />
-Javascript code: navigate("/home", { replace: true })
-After successful Login,we use the above code to go to home page
 'replace' attribute prevents users from pressing Back and returning to the login page after successful login.
-When to Use replace:
	1. After login/logout to prevent users from going back to the login page.
	2. For redirects where you don’t want the previous page in history.
	3. For reset navigation flows.

What replace does in ProtectedRoute

When a student opens /upload, the guard blocks them and sends them to /home with:

<Navigate to="/home" replace />
replace means: don’t add /upload to the browser history — replace the current history entry with /home.

With replace (what you have now)

You are on some page (e.g. /aboutus)
You go to /upload
You get redirected to /home
Browser Back does not return to /upload
It goes back to where you were before /upload (e.g. /aboutus)
Without replace

Same steps → redirected to /home
Browser Back would go to /upload again
The guard would redirect you to /home again — so Back feels stuck looping between /upload and /home
Short version: replace removes the blocked /upload visit from history so Back skips it and returns to the previous allowed page.

Code Splitting/Lazy Loading
===========================
-Eager Loading: Components are loaded when the application starts.
-Lazy Loading: Components are loaded only when they are required.

-Faster initial page load, Loads components only when needed
-React.lazy() is used to load a component dynamically.

  Eager Import: import OtherComponent from './OtherComponent';
  Lazy Import : const OtherComponent = React.lazy(() => import('./OtherComponent'));

Suspense
--------
-A lazy-loaded component must be wrapped inside Suspense.
-Suspense displays fallback content while the component is being loaded.

<Suspense fallback={<div>Loading...</div>}>
    <OtherComponent />
</Suspense>
